## 2. 基础知识与共性技术要求

以下要求同时适用于任务 1 和任务 2。

### 2.1 基础知识

- 数字逻辑与计算机组成：状态机、存储器、数据通路等基本概念。
- 神经网络前向计算：卷积、池化、全连接、ReLU 的计算方式。
- HLS（C/C++）实现。

### 2.2 面向硬件约束的网络轻量化设计

设计应主动适配底层硬件开销，任务书给出的方向包括：

- 使用符号位判别实现 ReLU。
- 使用比较逻辑实现最大池化。
- 精简全连接层规模。
- 在可行时移除偏置项，以降低片上存储和累加资源占用。
- 以参数规模和计算复杂度最小化为目标，降低硬件实现门槛。

### 2.3 定点量化与位宽寻优

任务书要求理解并实践以下流程：

1. 对模型参数做动态范围归一化，例如按最大绝对值缩放到 `[-1, 1]`。
2. 在 Python 仿真环境中做位宽敏感度分析。
3. 在保证准确率的前提下比较 8～16 位量化效果，选择性能趋于饱和的最小可用位宽。
4. 说明定点格式的符号位、整数位和小数位配置，以及相对于更高位宽的资源节省。

### 2.4 计算单元时分复用

不能只采用逐层直连的全展开结构；应考虑：

- 设计高复用度的计算核心。
- 通过控制状态机和数据流调度复用计算资源。
- 使多层卷积或全连接运算能够共享同一类算子模块。

### 2.5 资源约束与并行度权衡

应在不同位宽和并行度下开展设计空间探索（DSE），分析：

- 吞吐率与资源利用率的平衡。
- 高位宽或高并行度导致资源溢出的边界。
- 算力、带宽、面积、延迟和吞吐率之间的 PPA 权衡。

任务书以 625 FPS 作为吞吐率示例，并非当前 LeNet 实现已经必须达到的固定指标。

### 2.6 分层比对验证

应构建以软件模型为基准的 Testbench：

- 将测试样本注入硬件仿真环境。
- 统计推理准确率，并与算法模型对齐。
- 出现功能偏差时，逐层导出硬件中间特征图，与软件结果逐层比对，以定位故障模块。

### 2.7 Level 2 真实场景预处理与鲁棒性

针对真实采集图像与 MNIST 标准数据之间的分辨率、通道、畸变、光照和噪声差异，应建立端到端预处理链路，包括：

- 灰度转换。
- 反色处理。
- ROI 裁剪。
- 尺寸缩放。
- 无目标背景样本的抗干扰测试。

输出必须与 MNIST 一致，即 `28×28`、单通道灰度图。

## 4. 任务 2：LeNet 路线（当前选择）

### 4.1 任务目的

任务 2 以具有数据复用特性的卷积算子为实现对象，要求理解“循环变换即体系结构变换”：同一段算法在施加不同的循环展开、流水化和存储分割约束后，会映射成吞吐率、资源占用和访存需求不同的硬件结构。

具体目标是：

- 在指定器件的资源预算下，通过受控实验选择并行度。
- 形成算力、带宽和面积三者之间的工程权衡认识。
- 通过分模块实现和逐级验证分解复杂设计。
- 具备故障定位能力，回应数据通路/控制器设计和故障分析的课程要求。

### 4.3 当前 LeNet 实现的代码基线

现有 `level1` 是 Level 1 的硬件推理基线，数据流为：

```text
28x28 image
  -> Conv1 (6 output channels, 5x5) + bias + ReLU
  -> 2x2 max pool
  -> Conv2 (16 output channels, 5x5 over 6 channels) + bias + ReLU
  -> 2x2 max pool
  -> FC1 (256 -> 120) + bias + ReLU
  -> FC2 (120 -> 84) + bias + ReLU
  -> FC3 (84 -> 10) + bias
  -> logits and argmax prediction
```

已实现的数值和接口约束：

- 激活和参数：`ap_fixed<16, 6, AP_RND, AP_SAT>`。
- 累加器：`ap_fixed<32, 14, AP_RND, AP_SAT>`。
- `image` 和 `logits` 映射到 `gmem0`。
- 权重和偏置映射到 `gmem1`。
- 所有参数通过 `control` AXI-Lite bundle 暴露。
- 卷积和全连接权重使用扁平数组；卷积权重分别按 `[output][ky][kx]`、`[output][input][ky][kx]` 展平，全连接权重按 `[output][input]` 展平。
- 第二次池化结果按 `[channel][y][x]` 的 channel-major 顺序展平后进入 FC1。
- 未实现 softmax，因为它不改变最终 argmax 分类结果。

## 5. 任务 3：定点量化与设计空间探索（当前未实现）

任务 3 是任务 1 和任务 2 的共同延伸，不是独立选题，额外分值上限为 10 分。

### 5.1 进阶目的与衔接关系

- 直接复用已经通过基础任务验证的网络作为基线，不重复考核基础实现工作量。
- 基础版本的定点格式只是设计空间中的一个采样点，不是最终结论。
- 必须系统刻画精度—资源曲线，识别边际收益拐点或 Pareto 前沿，并结合应用场景推荐工作点。
- 将数值精度作为可以与面积、延迟、吞吐率互相交换的设计变量。
- 即使不进行上板测试，量化收益仍应由综合报告中的资源和时序数据体现。

### 5.2 量化理论与方法要求

1. 说明训练后量化（PTQ）和量化感知训练（QAT）的原理、精度边界和适用场景；本任务限定为 PTQ，不要求重训练。
2. 基于卷积层和全连接层的线性乘加特性以及 Softmax 的单调保序性，说明全局等比缩放不改变分类决策；通过一次前向传播统计最大绝对值，引入裕量系数计算缩放因子，把权重和中间激活映射到 `[-1, 1]`。
3. 在 8～16 bit 区间逐位评估定点模型相对浮点模型的推理误差，以保持准确率前提下的最小硬件位宽为寻优目标。
4. 探索权重和激活采用不同定点格式；非负特征可以省略符号位，以增加 1 位小数精度。
5. 分析逐层量化敏感度和混合精度，关联各层的动态范围、参数规模与量化噪声容忍度。
6. 分析 INT4 下的表征退化和误差累积；可进一步探究二值神经网络中乘累加变为 XNOR 与 `popcount` 的硬件收益及精度代价。

### 5.3 设计空间探索与评估方法

- 明确单变量扫描和双变量交叉采样的适用场景，遵守控制变量原则。
- 建立 Pareto Frontier 和非支配解筛选方法。
- 构建覆盖单位资源吞吐率、单位面积算力密度和峰值可达帧率的归一化指标。
- 建立性能提升相对资源开销的边际收益拐点判据。
- 将应用场景映射到指标权重：边缘侧关注资源/功耗，实时系统关注端到端延迟，云端关注吞吐率。
